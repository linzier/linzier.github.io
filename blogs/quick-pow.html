Quick Pow: How to Compute Exponentials Fast

2022-06-29 | Algorithms | 857 reads

The Problem

Compute n^m — raising a base n to an integer exponent m. This is one of the most common operations in programming, appearing everywhere from modular arithmetic in cryptography to matrix exponentiation in dynamic programming.

The straightforward approach is simple: multiply n by itself m times.

// Naive approach
func pow(n, m int) int {
    result := 1
    for i := 0; i < m; i++ {
        result *= n
    }
    return result
}

This requires m multiplications, giving us O(m) time complexity. For small exponents, this is fine. But what if m is a billion? A trillion? We need something better.

The Key Insight: Binary Decomposition

The core observation is that any exponent can be decomposed into a sum of powers of 2 — which is exactly what the binary representation of a number gives us.

Consider 3^29. The exponent 29 in binary is 11101, which means:

29 = 16 + 8 + 4 + 1
   = 2^4 + 2^3 + 2^2 + 2^0

Therefore:

3^29 = 3^16 * 3^8 * 3^4 * 3^1

Now here's the magic: we can compute each of these powers efficiently by repeated squaring:

  • Start with 3^1 = 3
  • Square it: 3^2 = 9
  • Square again: 3^4 = 81
  • Square again: 3^8 = 6561
  • Square again: 3^16 = 43046721

Each squaring doubles the exponent. We only need the powers where the corresponding bit in the binary representation of 29 is 1. Reading 11101 from right to left:

  • Bit 0 is 1: include 3^1
  • Bit 1 is 0: skip 3^2
  • Bit 2 is 1: include 3^4
  • Bit 3 is 1: include 3^8
  • Bit 4 is 1: include 3^16

Multiply them together: 3^1 * 3^4 * 3^8 * 3^16 = 3^29.

Counting the Multiplications

How many multiplications did we actually perform?

  • 4 squarings to compute 3^2, 3^4, 3^8, 3^16
  • 4 multiplications to combine the selected powers (since 4 bits are set in 11101, but we start with the first one, so 3 more multiplications... actually, let's count carefully)

Let's trace through the algorithm step by step. We maintain a running result and a current base:

  1. result = 1, base = 3, m = 29 (11101). Bit is 1: result = 1 * 3 = 3. base = 3^2 = 9.
  2. m = 14 (1110). Bit is 0: skip. base = 9^2 = 81 (= 3^4).
  3. m = 7 (111). Bit is 1: result = 3 * 81 = 243. base = 81^2 = 6561 (= 3^8).
  4. m = 3 (11). Bit is 1: result = 243 * 6561 = 1594323. base = 6561^2 (= 3^16).
  5. m = 1 (1). Bit is 1: result = 1594323 * 43046721 = 68630377364883. base = ... (not needed).

Total: 4 squarings + 4 multiplications into result = 8 multiplications, compared to 29 with the naive approach. Even better, the algorithm naturally handles this in O(log m) time.

Go Implementation

func quickPow(n, m int) int {
    result := 1
    base := n
    for m > 0 {
        if m&1 == 1 {
            result *= base
        }
        base *= base
        m >>= 1
    }
    return result
}

The algorithm is beautifully simple:

  • m & 1 == 1 checks if the lowest bit is 1 — if so, multiply the result by the current base.
  • base *= base squares the base for the next bit position.
  • m >>= 1 shifts right to process the next bit.

The loop runs exactly floor(log2(m)) + 1 times — the number of bits in m.

Benchmark Results

Let's compare three approaches in Go:

  1. Naive multiplication — the O(m) loop
  2. Quick pow — our binary exponentiation
  3. math.Pow — Go's standard library (float64-based)

Benchmarking 3^29:

BenchmarkNaive-8       50000000    24.3 ns/op
BenchmarkQuickPow-8    200000000    6.8 ns/op
BenchmarkMathPow-8     20000000     65.2 ns/op

The results speak for themselves:

  • Quick pow is about 3.5x faster than naive multiplication for m=29.
  • Quick pow is about 10x faster than math.Pow.

The advantage of quick pow grows as m increases. For m = 1,000,000, naive requires a million multiplications while quick pow needs only about 20.

Why is math.Pow so slow?

Go's math.Pow operates on float64 values and uses a general algorithm that handles fractional exponents, negative exponents, special cases (NaN, infinity), and maintains floating-point precision. All this generality comes at a cost. When you know you need integer exponentiation, quick pow eliminates all that overhead.

When to Use Quick Pow

Quick pow shines when:

  • You only need integer powers. No fractional or negative exponents.
  • You can ensure no overflow. Since we're working with integers, the result must fit in the integer type. For modular exponentiation (common in cryptography), you take the modulus at each step to prevent overflow.
  • Performance matters. In competitive programming, cryptographic operations, or any hot path where you're computing many exponentials.

Modular Exponentiation

A common variant is computing n^m mod p, widely used in cryptography (e.g., RSA). The modification is trivial — just take the modulus at each multiplication:

func modPow(n, m, p int) int {
    result := 1
    base := n % p
    for m > 0 {
        if m&1 == 1 {
            result = result * base % p
        }
        base = base * base % p
        m >>= 1
    }
    return result
}

This keeps all intermediate values bounded by p, preventing overflow as long as p * p fits in the integer type.

Summary

Quick pow reduces the time complexity of exponentiation from O(m) to O(log m) by exploiting the binary representation of the exponent. The algorithm is simple, fast, and widely applicable. When you need integer exponentiation and can guarantee no overflow, it's the clear winner over both naive multiplication and general-purpose floating-point power functions.

The key takeaway: whenever you see a problem that involves "repeated doubling," think binary decomposition. The same principle underlies fast multiplication (the Russian peasant algorithm), Fibonacci computation via matrix exponentiation, and many other algorithms.
