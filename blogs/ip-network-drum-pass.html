IP: The Network's Drum-Passing Game

2022-01-20 | Networking

Imagine a classic children's game: you pass an object from person to person, each handing it off to the next as quickly as possible until it reaches its target. The internet operates in a remarkably similar way. Your data — an email, a web page, a video — is broken down into small chunks called packets, and these packets hop from router to router across the globe until they reach their destination.

This is the world of IP (Internet Protocol), the fundamental protocol that makes the internet possible.

IP as a Relay Race

When you send data over the internet, it does not travel in one continuous stream from your computer to the destination server. Instead, it is segmented into small, self-contained units called packets, each charting its own path across the network.

Think of it as a global relay race. A packet starts at your computer and is handed off to your local router. The router inspects the packet's destination address and forwards it to the next hop. That router passes it to the next, and so on, until the packet arrives at its final destination.

Each "handoff" is called a hop. A typical packet might make 10 to 20 hops on its journey from your computer to a server on the other side of the world. Each hop takes a fraction of a second (usually a few milliseconds), and the entire journey is completed in the blink of an eye.

Here is the ingenious part: different packets from the same message don't have to take the same route. Packet 1 might route through New York, while Packet 2 transits through London. The network is highly dynamic — routers go down, links get congested, and the routing system adapts in real time.

This is called packet switching, and it is the foundational design principle of the internet. It is what makes the internet incredibly robust, scalable, and efficient.

IP Addresses: The Network's Phone Book

Every device on the internet needs an address so that packets know where to go. That address is an IP address.

IPv4 Addresses

An IPv4 address is a 32-bit number, usually written in dotted-decimal notation as four numbers separated by dots. Each number represents one byte (8 bits) and ranges from 0 to 255.

For example: 192.168.1.100

This is actually the number 192×256³ + 168×256² + 1×256 + 100 = 3,232,235,876. But thankfully, nobody writes it that way.

An IPv4 address has two parts:

  • Network part: identifies which network the device belongs to. Think of it as the "street name."
  • Host part: identifies the specific device within that network. Think of it as the "house number."

For example, in the address 192.168.1.100, the network part might be 192.168.1 and the host part might be 100. All devices on the same local network share the same network part.

Subnet Masks

How do you know which part of the address is the network part and which is the host part? That is what the subnet mask tells you.

A subnet mask is another 32-bit number that, when combined with the IP address, reveals the network and host parts. The subnet mask has all 1s in the network part and all 0s in the host part.

For example, a subnet mask of 255.255.255.0 means:

  • The first three bytes (255.255.255) are the network part.
  • The last byte (0) is the host part.

So with the address 192.168.1.100 and subnet mask 255.255.255.0, the network is 192.168.1.0 and the host is 100.

Subnet masks can also be written in CIDR notation (Classless Inter-Domain Routing). Instead of writing the full mask, you write a slash followed by the number of 1-bits. For example, 255.255.255.0 is /24 (24 ones followed by 8 zeros). So 192.168.1.100/24 means the network is 192.168.1.0/24.

IPv6: The Next Generation

While IPv4 provides about 4.3 billion addresses (2³²), the explosion of internet-connected devices has exhausted this pool. IPv6 was designed to solve this crisis by using 128-bit addresses, providing 3.4×10³&sup8; addresses — enough to assign a unique IP address to every single grain of sand on Earth.

IPv6 addresses are written in hexadecimal, with eight groups of four hex digits separated by colons:

2001:0db8:85a3:0000:0000:8a2e:0370:7334

Leading zeros in each group can be omitted, and consecutive groups of zeros can be replaced with :: (but only once per address):

2001:db8:85a3::8a2e:370:7334

IPv6 adoption has been slow but steady. Today, over 40% of Google's traffic comes from IPv6.

Routing: How Routers Decide Where to Forward Packets

When a router receives a packet, it must determine where to send it next. This process is known as routing.

Every router maintains a routing table, which acts as a map of the network. The routing table tells the router: "To reach network X, forward the packet to router Y" (where router Y is called the next hop).

When a packet arrives, the router inspects its destination IP address, looks it up in the routing table, and dispatches it to the correct next hop. If no route matches, the packet is discarded, and an ICMP "Destination Unreachable" error is sent back to the sender.

How Routing Tables Are Built

Except in small networks, routing tables are rarely configured manually. Instead, routers use routing protocols to dynamically exchange information and build their tables automatically.

There are two main types of routing protocols:

  • Interior Gateway Protocols (IGPs): Used within a single organization or autonomous system (AS). Examples include OSPF (Open Shortest Path First) and EIGRP (Enhanced Interior Gateway Routing Protocol). These protocols find the shortest path within a network.
  • Exterior Gateway Protocols (EGPs): Used between different autonomous systems. The protocol used on the public internet is BGP (Border Gateway Protocol). BGP is the glue that holds the internet together — it allows different networks (ISPs, companies, universities) to exchange routing information and reach each other.

BGP is a sophisticated, policy-driven protocol. Unlike IGPs, which focus purely on finding the shortest path, BGP allows network administrators to enforce business preferences and routing policies. For example, a company might choose to route traffic through one ISP over another to save costs, even if that path is technically longer.

The Journey of a Packet

Let's trace the path of a packet traveling from your computer to a web server at 93.184.216.34 (the IP address of example.com):

  1. Your computer checks the destination IP. Recognizing that it is not on your local network (based on the subnet mask), it dispatches the packet to your default gateway (your home router).
  2. Your home router performs NAT (see below) and forwards the packet to your ISP's edge router.
  3. Your ISP's router looks up 93.184.216.34 in its routing table and forwards it to the next ISP or transit provider.
  4. The packet hops through several transit routers, drawing closer to the destination network with each step.
  5. Finally, the packet arrives at the destination network's edge router (e.g., the data center hosting example.com), which delivers it to the target server.

You can see this journey yourself using the traceroute command (or tracert on Windows):

$ traceroute 93.184.216.34
 1  192.168.1.1      1.234 ms  1.100 ms  1.050 ms
 2  10.0.0.1         5.678 ms  5.500 ms  5.400 ms
 3  72.14.215.85     10.123 ms 10.100 ms 10.050 ms
 ...
12  93.184.216.34    50.456 ms 50.400 ms 50.350 ms

Each line is a hop. The times are the round-trip time (RTT) for each hop. You can see the packet crossing your local network, then your ISP's network, then the broader internet, and finally reaching the destination.

NAT: Network Address Translation

If you check your computer's IP address, you might see a private address like 192.168.1.100. Yet when you visit a website, the server sees a completely different IP — your ISP's public IP address. How does this happen?

The magic that makes this possible is NAT (Network Address Translation).

Private vs. Public IPs

Not every device on the internet requires a globally unique IP address. Most devices reside on private networks (home or office networks) and use private IP addresses that are non-routable on the public internet.

The private IP address ranges are:

  • 10.0.0.0 to 10.255.255.255 (10.0.0.0/8) — 16.7 million addresses
  • 172.16.0.0 to 172.31.255.255 (172.16.0.0/12) — 1 million addresses
  • 192.168.0.0 to 192.168.255.255 (192.168.0.0/16) — 65,536 addresses

These ranges are reserved for private use. Any device can use them on its internal network without conflicting with the public internet.

How NAT Works

Your home router sits between your private network and the public internet. It holds two IP addresses:

  • A private IP address on your local network (e.g., 192.168.1.1).
  • A public IP address leased by your ISP (e.g., 73.45.123.89).

When your computer (192.168.1.100) sends a packet to the internet, it transits through your router. The router performs NAT:

  1. It replaces the source IP in the packet header (your private IP, 192.168.1.100) with its public IP (73.45.123.89).
  2. It logs this translation in a NAT table: "Connection from 192.168.1.100:12345 is mapped to 73.45.123.89:54321."
  3. It forwards the packet to the destination.

When the response returns from the server to 73.45.123.89:54321, the router consults its NAT table, matches it to 192.168.1.100:12345, replaces the destination address with your private IP, and forwards the packet back to your computer.

This is technically called NAPT (Network Address Port Translation) or masquerading. It allows hundreds of devices on a private network to share a single public IP address, using unique port numbers to keep their connections distinct.

NAT is the primary reason the internet did not run out of IPv4 addresses decades ago. It is a highly practical, enduring workaround that has extended the lifespan of IPv4 by decades.

The Journey of a Packet: From Your Computer to a Server

Let's put it all together. You type http://example.com into your browser. What happens?

  1. DNS Resolution: Your browser must first resolve the IP address of example.com. It queries a DNS server (which we will cover in detail in a future article) and receives 93.184.216.34.
  2. Packet Creation: Your browser constructs an HTTP request and hands it to the operating system's network stack. The OS segments the data into packets, stamping each with an IP header containing your source IP (private) and the destination IP (93.184.216.34).
  3. NAT: The packets go to your home router, which replaces your private IP with its public IP.
  4. Routing: The packets hop from router to router across the internet, each router consulting its routing table to determine the optimal next hop.
  5. Arrival: The packets reach the server at 93.184.216.34. The server's network stack reassembles them into the original, complete HTTP request.
  6. Response: The server processes the request and sends back an HTTP response, which is also segmented into packets. These packets make the reverse journey, hopping back to your router.
  7. Reverse NAT: Your router receives the response packets, performs reverse NAT (restoring your private IP as the destination), and forwards them to your computer.
  8. Rendering: Your browser receives the HTTP response and renders the web page.

All of this unfolds in a fraction of a second. The next time you load a web page, appreciate the incredible journey those packets take — leaping across routers, bridging oceans and continents, all to deliver a simple webpage or image.

Summary

  1. IP is a packet-switched protocol: data is partitioned into packets that hop dynamically from router to router.
  2. IP addresses identify network endpoints. IPv4 uses 32-bit addresses (dotted-decimal), while IPv6 uses 128-bit addresses (hexadecimal).
  3. An IP address is split into a network part and a host part, defined by the subnet mask.
  4. Routers use routing tables to direct packets. These tables are built dynamically using routing protocols (like OSPF and BGP).
  5. NAT allows multiple devices on a private network to share a single public IP address, prolonging the utility of IPv4.
  6. The lifecycle of a packet involves DNS resolution, NAT, multi-hop routing, and destination reassembly.

IP is the elegant, resilient foundation of the internet. It makes no guarantees of delivery (that is TCP's job), but it reliably delivers packets from point A to point B, one hop at a time — a global game of pass-the-parcel.
