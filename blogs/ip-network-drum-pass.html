IP: The Network's Drum-Passing Game

2022-01-20 | Networking

Imagine a children's game: you pass a drum from person to person, each person handing it to the next until it reaches the performer. The internet works in a remarkably similar way. Your data — an email, a web page, a video — is broken into small chunks called packets, and these packets hop from router to router across the globe until they reach their destination.

This is the world of IP (Internet Protocol), the fundamental protocol that makes the internet possible.

IP as a Relay Race

When you send data over the internet, it does not travel in one continuous stream from your computer to the destination server. Instead, it is chopped into small pieces called packets. Each packet is an independent unit that makes its own way across the network.

Think of it like a relay race. A packet starts at your computer and is handed to your local router. The router looks at the packet's destination address and passes it to the next router. That router passes it to the next, and so on, until the packet reaches its destination.

Each "handoff" is called a hop. A typical packet might make 10 to 20 hops on its journey from your computer to a server on the other side of the world. Each hop takes a small amount of time (usually a few milliseconds), and the total journey might take anywhere from a few milliseconds to a few seconds.

Here is the remarkable part: different packets from the same message might take different routes. Packet 1 might go through New York, while Packet 2 goes through London. The network is dynamic — routers go down, links get congested, and the routing system adapts in real time.

This is called packet switching, and it is the fundamental design principle of the internet. It is what makes the internet robust, scalable, and efficient.

IP Addresses: The Network's Phone Book

Every device on the internet needs an address so that packets know where to go. That address is an IP address.

IPv4 Addresses

An IPv4 address is a 32-bit number, usually written in dotted-decimal notation as four numbers separated by dots. Each number represents one byte (8 bits) and ranges from 0 to 255.

For example: 192.168.1.100

This is actually the number 192×256³ + 168×256² + 1×256 + 100 = 3,232,235,876. But nobody writes it that way.

An IPv4 address has two parts:

  • Network part: identifies which network the device belongs to. Think of it as the "street name."
  • Host part: identifies the specific device within that network. Think of it as the "house number."

For example, in the address 192.168.1.100, the network part might be 192.168.1 and the host part might be 100. All devices on the same local network share the same network part.

Subnet Masks

How do you know which part of the address is the network part and which is the host part? That is what the subnet mask tells you.

A subnet mask is another 32-bit number that, when combined with the IP address, reveals the network and host parts. The subnet mask has all 1s in the network part and all 0s in the host part.

For example, a subnet mask of 255.255.255.0 means:

  • The first three bytes (255.255.255) are the network part.
  • The last byte (0) is the host part.

So with the address 192.168.1.100 and subnet mask 255.255.255.0, the network is 192.168.1.0 and the host is 100.

Subnet masks can also be written in CIDR notation (Classless Inter-Domain Routing). Instead of writing the full mask, you write a slash followed by the number of 1-bits. For example, 255.255.255.0 is /24 (24 ones followed by 8 zeros). So 192.168.1.100/24 means the network is 192.168.1.0/24.

IPv6: The Next Generation

IPv4 provides about 4.3 billion addresses (2³2;). That sounds like a lot, but with the explosion of internet-connected devices, we ran out. IPv6 was designed to solve this problem by using 128-bit addresses, providing 3.4×10³&sup8; addresses — enough to give every grain of sand on Earth its own IP address.

IPv6 addresses are written in hexadecimal, with eight groups of four hex digits separated by colons:

2001:0db8:85a3:0000:0000:8a2e:0370:7334

Leading zeros in each group can be omitted, and consecutive groups of zeros can be replaced with :: (but only once per address):

2001:db8:85a3::8a2e:370:7334

IPv6 adoption has been slow but steady. Today, over 40% of Google's traffic comes from IPv6.

Routing: How Routers Decide Where to Forward Packets

When a router receives a packet, it needs to decide where to send it next. This process is called routing.

Every router maintains a routing table, which is essentially a map of the network. The routing table tells the router: "To reach network X, send the packet to router Y" (where router Y is called the next hop).

When a packet arrives, the router examines the destination IP address, looks it up in the routing table, and forwards the packet to the appropriate next hop. If no matching route is found, the packet is dropped and an error message (ICMP Destination Unreachable) is sent back to the sender.

How Routing Tables Are Built

Routing tables are not manually configured (except for small networks). Instead, routers use routing protocols to exchange information and build their tables automatically.

There are two main types of routing protocols:

  • Interior Gateway Protocols (IGPs): Used within a single organization or autonomous system (AS). Examples include OSPF (Open Shortest Path First) and EIGRP (Enhanced Interior Gateway Routing Protocol). These protocols find the shortest path within a network.
  • Exterior Gateway Protocols (EGPs): Used between different autonomous systems. The protocol used on the public internet is BGP (Border Gateway Protocol). BGP is the glue that holds the internet together — it allows different networks (ISPs, companies, universities) to exchange routing information and reach each other.

BGP is a complex, policy-driven protocol. Unlike IGPs, which focus on finding the shortest path, BGP allows network administrators to express preferences and policies. For example, a company might prefer to send traffic through one ISP over another, even if the other path is technically shorter.

The Journey of a Packet

Let's trace the journey of a packet from your computer to a web server at 93.184.216.34 (the IP address of example.com):

  1. Your computer checks the destination IP. It is not on your local network (based on the subnet mask), so the packet is sent to your default gateway (your home router).
  2. Your home router performs NAT (see below) and forwards the packet to your ISP's router.
  3. Your ISP's router looks up 93.184.216.34 in its routing table and forwards the packet to the next ISP or transit provider.
  4. The packet hops through several more routers, each one getting closer to the destination network.
  5. Finally, the packet reaches the router at the destination network (e.g., the data center hosting example.com), which delivers it to the server.

You can see this journey yourself using the traceroute command (or tracert on Windows):

$ traceroute 93.184.216.34
 1  192.168.1.1      1.234 ms  1.100 ms  1.050 ms
 2  10.0.0.1         5.678 ms  5.500 ms  5.400 ms
 3  72.14.215.85     10.123 ms 10.100 ms 10.050 ms
 ...
12  93.184.216.34    50.456 ms 50.400 ms 50.350 ms

Each line is a hop. The times are the round-trip time (RTT) for each hop. You can see the packet crossing your local network, then your ISP's network, then the broader internet, and finally reaching the destination.

NAT: Network Address Translation

If you check your computer's IP address, you might see something like 192.168.1.100. But when you visit a website, the server sees a completely different IP address — your ISP's public IP address. How does this work?

The answer is NAT (Network Address Translation).

Private vs. Public IPs

Not every device on the internet needs a globally unique IP address. Many devices are on private networks (home networks, office networks) and use private IP addresses that are not routable on the public internet.

The private IP address ranges are:

  • 10.0.0.0 to 10.255.255.255 (10.0.0.0/8) — 16.7 million addresses
  • 172.16.0.0 to 172.31.255.255 (172.16.0.0/12) — 1 million addresses
  • 192.168.0.0 to 192.168.255.255 (192.168.0.0/16) — 65,536 addresses

These ranges are reserved for private use. Any device can use them on its internal network without conflicting with the public internet.

How NAT Works

Your home router sits between your private network and the public internet. It has two IP addresses:

  • A private IP address on your local network (e.g., 192.168.1.1).
  • A public IP address assigned by your ISP (e.g., 73.45.123.89).

When your computer (192.168.1.100) sends a packet to the internet, the packet goes to your router. The router performs NAT:

  1. It replaces the source IP address in the packet header (your private IP, 192.168.1.100) with its own public IP (73.45.123.89).
  2. It records the translation in a NAT table: "Connection from 192.168.1.100:12345 is now 73.45.123.89:54321."
  3. It forwards the packet to the internet.

When the response comes back from the server to 73.45.123.89:54321, the router looks up the NAT table, finds that this corresponds to 192.168.1.100:12345, replaces the destination address, and forwards the packet to your computer.

This is called NAPT (Network Address Port Translation) or masquerading. It allows hundreds of devices on a private network to share a single public IP address, each distinguished by a different port number.

NAT is why the internet did not run out of IPv4 addresses sooner. It is a pragmatic hack that extended the life of IPv4 by decades.

The Journey of a Packet: From Your Computer to a Server

Let's put it all together. You type http://example.com into your browser. What happens?

  1. DNS resolution: Your browser needs to find the IP address of example.com. It queries a DNS server (we will cover DNS in detail in the next article) and gets back 93.184.216.34.
  2. Packet creation: Your browser creates an HTTP request and hands it to the operating system's network stack. The OS breaks the data into packets, each with an IP header containing the source IP (your private IP) and destination IP (93.184.216.34).
  3. NAT: The packets go to your home router, which performs NAT, replacing your private IP with its public IP.
  4. Routing: The packets hop from router to router across the internet, each router consulting its routing table to decide the next hop.
  5. Arrival: The packets reach the server at 93.184.216.34. The server's network stack reassembles the packets into the complete HTTP request.
  6. Response: The server processes the request and sends back an HTTP response, which is also broken into packets. These packets make the reverse journey, hopping from router to router back to your router.
  7. Reverse NAT: Your router receives the response packets, performs reverse NAT (replacing the destination public IP with your private IP), and forwards them to your computer.
  8. Rendering: Your browser receives the HTTP response and renders the web page.

All of this happens in a fraction of a second. The next time you load a web page, take a moment to appreciate the incredible journey those packets make — hopping from router to router, crossing oceans and continents, all to bring you a cat photo or a news article.

Summary

  1. IP is a packet-switched protocol: data is broken into packets that hop from router to router.
  2. IP addresses identify devices. IPv4 uses 32-bit addresses (dotted-decimal), IPv6 uses 128-bit addresses (hexadecimal).
  3. An IP address has a network part and a host part, determined by the subnet mask.
  4. Routers use routing tables to decide where to forward packets. Routing tables are built by routing protocols (OSPF, BGP).
  5. NAT allows multiple devices on a private network to share a single public IP address, extending the life of IPv4.
  6. The journey of a packet involves DNS resolution, NAT, routing across multiple hops, and reassembly at the destination.

IP is the foundation of the internet. It is simple, robust, and scalable. It does not guarantee delivery (that is TCP's job), but it gets packets from here to there, one hop at a time, like a global game of drum pass.
