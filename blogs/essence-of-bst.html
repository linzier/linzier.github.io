The Essence of Binary Search Trees

2023-04-03 | Data Structures

Introduction

I plan to write a series of articles exploring tree-based data structures: binary search trees, red-black trees, skip lists, and B-trees. Each of these structures was designed to solve the same fundamental challenge: how to efficiently insert, delete, and search for elements within a massive dataset.

In this first installment, we cover the foundation of this family: the Binary Search Tree (BST).

The Basic Problem

How do you quickly locate a specific phone number, say 13012345432, among ten million entries?

The most naive approach: a linear scan, running in O(n) time.

The most efficient approach for lookup: a hash table, offering O(1) time complexity.

The Problem with Hash Tables

While hash tables offer exceptional lookup performance, they come with a major catch.

How would you find all phone numbers that fall between 13011111111 and 13022222222 among those ten million entries?

This is a classic range query. Because hash functions generate randomized indices, they destroy any natural ordering of the keys, making efficient range searches practically impossible.

Binary Search on Sorted Arrays

If the phone numbers are sorted, binary search can locate any number in O(log n) time. For ten million entries, you need at most 24 comparisons.

The Problem with Binary Search

Binary search relies on an array, however — and arrays are inefficient for insertions and deletions.

The Core Insight: From Arrays to Trees

What if we replace the array's contiguous memory with linked nodes, and replace the concept of left and right sub-arrays with left and right pointers? That conceptual shift gives us the Binary Search Tree.

Searching in a Binary Search Tree

The search logic is structurally identical to binary search — we just navigate left or right subtrees instead of slicing sub-arrays.

Special Case: Finding the Minimum Element

To find the minimum, start at the root and follow the left child pointers until reaching a leaf.

In-Order Traversal

An in-order traversal follows the sequence: left subtree → current node → right subtree. This traversal visits the nodes in perfectly sorted order.

Handling Range Queries

By applying range constraints to our traversal, we can prune subtrees that fall outside our target bounds.

Insertion

  1. Traverse the tree to find the correct insertion point as if searching for the value.
  2. Insert the new node as a leaf at that position.

Time complexity: O(log n).

Deletion

Case 1: Deleting a leaf node.

Case 2: The node to be deleted has only one child.

Case 3: The node to be deleted has both left and right children — replace its value with the minimum node from its right subtree (its in-order successor), then recursively delete that minimum node.

The Problem with Binary Search Trees

Because new nodes are always inserted as leaves, the tree can become severely unbalanced and skewed depending on insertion order.

Summary

  1. Hash tables excel at exact-match queries but fail at range queries due to their unordered nature.
  2. Binary search on sorted arrays handles both exact-match and range queries efficiently, but suffers from slow insertions and deletions.
  3. Binary Search Trees (BSTs) theoretically support all of these operations in O(log n) time.
  4. Unbalanced BSTs are prone to structural skew, degenerating into a linked list in the worst-case scenario.
  5. To solve this skewing problem, we rely on self-balancing data structures such as red-black trees, skip lists, and B-trees.
